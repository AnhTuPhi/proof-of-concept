POC 30 · Tiered Rate Limiting

Token bucket × 3 dimensions (user, IP, endpoint). 429 with Retry-After.

1 · Pick user & tier

Tiers map to (capacity, refill). For the demo:
  • FREE — 20 req / 60s, burst 20
  • PRO — 120 req / 60s
  • ENTERPRISE — 600 req / 60s (soft cap, still throttled at the per-IP layer)

Refill is lazy — on each read, tokens are added proportional to elapsed time. A sliding window in disguise.

Why three dimensions?
• user bucket — fair share per account, sized to tier
• ip bucket — catches NAT'd traffic / abuse from one origin
• endpoint bucket — soft cap to protect a single hot path from a stampede
Any one trips → 429. Keeping them separate stops one hot endpoint from burning a user's whole quota.
