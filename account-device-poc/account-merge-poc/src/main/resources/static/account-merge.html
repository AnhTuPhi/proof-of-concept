Users in DB

What happens when you click "Merge"

1
Preview conflicts — diff every field, count rows across auth_methods, trade_orders, watchlists.
2
Pick winners — for each conflicting field, the operator (or UI) picks which value survives on the merged user.
3
Reassign FKs — single transaction: UPDATE auth_methods SET user_id = target WHERE user_id = source across every FK table.
4
Soft-mark loser — source user becomes MERGED_REDIRECT with merged_into_user_id = target. Never deleted.
5
Login redirect — a Google OAuth login still resolves the old user row, which then redirects to the surviving account.
