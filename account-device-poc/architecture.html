Account Merge port 8081

User signed up via Google two years ago, forgot, and just signed up again with email + password. Two users rows, one human. Merge their data across N tables without hard-deleting either — both auth methods must keep working.
🛡️ Protecting: financial trade records, the audit trail, and the invariant that every auth method a person owns resolves to one live account.

⚠️ Tech debt to acknowledge

  • In-memory H2 stands in for Oracle (create-drop).
  • No pessimistic lock on the two users → concurrent merges can interleave.
  • Redirect chains can grow; needs a background flatten job (A→B→C ⇒ A→C).
  • Bulk JPQL bypasses the persistence context — a footgun if the flow grows.
  • Only 3 scalar fields resolve conflicts; real merges dedupe collections too.

Multi-Device Sessions port 8082

Phone, laptop, tablet all logged in. User changes password → every in-flight JWT must die instantly. Refresh tokens rotate on every use, and reuse of a rotated token is treated as theft.
🛡️ Protecting: the ability to revoke trust immediately on a stolen device, and to detect refresh-token theft instead of silently allowing it.

⚠️ Tech debt to acknowledge

  • All state in-memory (ConcurrentHashMap) — biggest scale-out blocker.
  • Toy password hash (Integer.toHexString(hashCode())) — use BCrypt/Argon2.
  • Symmetric HMAC secret in config — prefer asymmetric signing + key rotation.
  • No absolute session lifetime cap; refreshing session lives forever.
  • No eviction of expired/revoked sessions — map grows unbounded.

Tiered Rate Limiting port 8083

Token-bucket limits per plan tier (Free / Pro / Enterprise) across three independent dimensions — user, IP, endpoint. Any dimension tripping ⇒ 429 with a precise Retry-After.
🛡️ Protecting: service availability & fairness — paying tiers keep their quota, abusers get contained, honest clients get actionable back-pressure.

The flow — one request draws from three buckets at once

per-user (tiered) per-IP per-endpoint

Inside one bucket — burst vs steady-state, refilled lazily

capacity = burst

A full bucket lets a client spend capacity tokens in one instant — the legitimate "page fires 10 quotes at once" case.

refill rate = steady-state

tokens += elapsed × (refillTokens / interval), capped at capacity. Computed on read — no scheduler thread.

precise Retry-After

On a miss: ceil(deficit / tokensPerMs) gives the exact wait for this bucket. The service returns the max across tripped dimensions so the client's retry clears every limit at once.

thread safety

synchronized tryConsume/snapshot; dimension maps are ConcurrentHashMap.

⚠️ Tech debt to acknowledge

  • Per-pod buckets — N replicas ⇒ N× the real limit. Needs atomic Redis Lua.
  • Tiers are a hardcoded enum; real systems read a tier_quotas table.
  • IP & endpoint maps never evict — needs TTL/LRU.
  • Every call costs 1 token; expensive endpoints should cost more.
  • Wall-clock refill drifts across hosts — a distributed version must use the Redis clock.

Scaling & Consistency k8s / VMs

Every POC is correct on one process. The moment you run N replicas behind a load balancer, each holds its own private copy of "the truth." Full detail in CONSISTENCY.md.

Why it breaks — state trapped in the JVM heap

What breaks per POC, and the fix

POCState todayBreaks because…Fix
28 Merge H2 in-memory per-pod H2 diverges; concurrent merges race → redirect cycles shared Oracle + SELECT…FOR UPDATE (ordered) + @Version
29 Sessions ConcurrentHashMap revoke / tv bump invisible to other pods — a real security hole Redis: atomic INCR tv, shared session store, Lua refresh rotation
30 Rate Limit ConcurrentHashMap N pods ⇒ N× the limit, non-deterministic under an HPA single atomic Redis Lua refill→check→decrement + key TTL

Kubernetes-specific gotchas

  • Rolling deploys run mixed versions — keep Redis key schema & JWT claims backward-compatible for one release (expand → migrate → contract).
  • Pods are cattle — SIGTERM any time; never keep authoritative state only in a pod.
  • HPA vs rate limiter — if buckets aren't centralized, scaling up to shed load also raises the effective limit; the limiter fights the autoscaler.
  • Readiness ≠ liveness — lose Redis/Oracle ⇒ fail readiness (stop traffic), not liveness (avoid restart storms).
  • No sticky sessions — externalizing state means any pod serves any request; affinity hides the bug and breaks on rebalance.

Bottom line: scaling this suite is not a rewrite — the algorithms are already right. It's a relocation of state out of the JVM into Redis (atomic ops) and shared Oracle (row locking), leaving every replica stateless.
