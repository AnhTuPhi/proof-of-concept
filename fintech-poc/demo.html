1 Idempotent payment

The client retries because the network ate the response. We must not double-charge.

Invariant: For a given Idempotency-Key, exactly one payment row is created and exactly one response is returned to every caller, forever.

The flow

POST /payments Idempotency-Key: req-001 Body: {amount, currency, customerId} │ ▼ fingerprint = SHA-256(canonical(body)) │ ▼ INSERT INTO idempotency_record (key, fingerprint, status='IN_FLIGHT') │ ├── UNIQUE conflict? ──► read winner's row, replay response │ ▼ Execute charge → Payment row │ ▼ UPDATE idempotency_record SET status='COMPLETED', response_json=<JSON> │ ▼ Return response (replayed=false the first time, true after)

Key tech by responsibility

UNIQUE constraint
Arbitrates concurrent inserts. First writer wins; DB raises DataIntegrityViolation for the rest.
SHA-256 fingerprint
Catches same-key-different-body tampering or client bugs. 409 conflict, no charge.
REQUIRES_NEW propagation
Claim commits in its own transaction so the outer failure can't wipe the claim.
Response replay
Stored JSON on the record; every retry gets byte-identical response with replayed=true.

2 Wallet concurrency

100k VND wallet. 150 concurrent 1k debits. Exactly 100 must succeed. Balance never negative.

Invariant: wallet.balance ≥ 0 under all interleavings. Successful debits = ledger entries. Ending balance = starting − Σ(successful debits).

The three strategies

PESSIMISTIC
SELECT ... FOR UPDATE — DB serializes waiters on the row. Simple, high contention friendly.
OPTIMISTIC
@Version — version check on save; retry with exp backoff on conflict. Best at low contention.
CONDITIONAL_UPDATE
UPDATE ... WHERE balance ≥ :amt — DB enforces invariant atomically. Lowest latency.

The bug that all three prevent

// NAIVE (broken) Wallet w = repo.findById(id); // reads 100,000 if (w.balance >= amount) { // check on stale value w.debit(amount); // in-memory 99,000 repo.save(w); // last writer wins } // Two threads read 100k concurrently, // both pass check, both write 99k. // Ledger gets two entries. Balance still 99k. // LOST UPDATE.

3 Reconciliation

Daily job: join internal ledger against provider settlement report. Four break categories.

Invariant: Every settled transaction is either matched to an internal record or booked as a specific break type. Re-runs never re-break already-matched rows.

Break types

TypeMeaningOwner
MISSING_AT_PROVIDERWe shipped, they didn't settleOps
MISSING_AT_INTERNALThey settled, we have no recordEngineering
AMOUNT_MISMATCHSame ref, different amountFinance
CURRENCY_MISMATCHWrong ccy settledProvider config

Match algorithm

for each internal txn (matched=false): provider = lookup by providerRef if provider is null → MISSING_AT_PROVIDER elif currency differs → CURRENCY_MISMATCH elif amount differs → AMOUNT_MISMATCH elif |occurredAt - settledAt| > 48h → break else: mark BOTH matched=true for each provider txn (matched=false): if no internal with that providerRef → MISSING_AT_INTERNAL

4 Refund flow

Refund the actual paid amount, not the face value. Fall back cleanly when the card is gone. Cap at remaining refundable.

Invariant: Σ refunds ≤ paid. Refund amount computed from paidAmount (net of coupon), not faceValue. State transitions one-way and validated.

Channel selection (fallback logic)

Original methodFallback channel
ACTIVEORIGINAL_CARD
EXPIREDBANK_TRANSFER
REMOVEDSTORE_CREDIT

Reject rules

  • Older than 180 days → refund window expired
  • Requested > remaining refundable → over-refund
  • Illegal state transition → throw
  • Same idempotency key → replay same refund (no new payout)

5 Multi-currency

Customer sees USD, pays VND, refunds in USD at the original locked rate. FX P&L isolated.

Invariant: Refund in original presentment currency at original locked rate. FX delta between locked and current market rate is booked to a dedicated P&L account, never mixed into the transaction.

Three moving parts

Quote (TTL 15m)
Rate = market × (1 − margin). Expires at absolute timestamp; expired = reject.
Payment
Stores lockedRate on the row. Book margin delta to FxPnlEntry(MARGIN).
Refund
Settlement = presentment × original locked rate. Delta vs current rate → FxPnlEntry(FX_DELTA_REFUND).

Ledger picture

quote: 1 USD → 24,000 VND (locked) pay: $10 → ₫240,000 settle margin ₫1,200 → FxPnlEntry(MARGIN) --- 30 days later, market moves --- market: 1 USD → 26,000 VND refund: $10 (customer receives USD) settle at LOCKED → ₫240,000 (our cost, at market: ₫260,000) delta ₫20,000 → FxPnlEntry(FX_DELTA_REFUND)
